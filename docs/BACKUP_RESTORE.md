# Backup and restore

JETT exports documents, records, reading positions, arrived moments, organization spaces, space feeds, user-facing settings and the durable outbound queue as one encrypted JSON envelope. The user supplies and confirms a passphrase of at least 12 characters. Web Crypto derives a 256-bit AES-GCM key with PBKDF2-SHA-256, a random 16-byte salt and 310,000 iterations, then encrypts with a random 12-byte IV. The passphrase is neither serialized nor stored by JETT and cannot be recovered by the application.

Settings offers a staged restore: choosing an encrypted file asks for its passphrase, authenticated decryption and structural validation complete before document, record and arrival counts appear, and no device data changes during that inspection. A separate **restore this backup** action replaces the five application IndexedDB collections in one transaction, restores settings and organization data, then reloads from persistence. Queued sends are restored only when the export's device identity matches the current device. Legacy plaintext `jt-export` files remain importable for migration, with an explicit warning to make the next backup encrypted; new downloads use only the encrypted envelope.

The validator rejects malformed JSON, foreign formats, missing collections, duplicate document IDs, records without their documents, reading positions without their documents, invalid settings and organization records that fail the existing organization schemas. A database failure restores the previous local settings and organization blob rather than leaving those surfaces changed.

`test/backup.test.mjs` covers encryption round-trip, absence of plaintext and passphrase from the envelope, security-parameter validation, wrong-passphrase failure and authenticated tamper rejection. The desktop production-browser journey verifies passphrase confirmation, exports populated data through the encrypted boundary, proves a wrong passphrase cannot enable restore, unlocks with the correct passphrase, stages the file, restores it, waits through reload and compares restored document, record, arrival and same-device outbox IDs with the source export.

## Current boundary

The encrypted export does not contain pairing credentials or the transport delivery log. The product copy names the device boundary. A queued send carries device-bound transport identity, so JETT refuses to replay another device's queue while still restoring the portable saved data. Encryption protects a backup when it is copied or stored; it does not protect data while the application is open, escrow a lost passphrase, schedule backups, prove external backup custody or replace physical-device restore testing. This slice proves encrypted saved application-data and same-device outbox recovery; it is not yet a complete device migration or physical-device restore.
