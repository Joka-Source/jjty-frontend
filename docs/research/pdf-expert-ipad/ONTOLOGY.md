# JETT / PDF Expert research ontology — first online pass

8 September 2026. Qualitative desk research, not a representative survey.
Primary target: current iPad PDF Expert; direct device session deferred.

## Units of analysis

One observation links: user job → document/object → context → action → visible
feedback → durable outcome → failure/recovery → source evidence → JETT test.
Keep platform, date, stated version, evidence type and uncertainty with it.
Separate user sentiment, documented behavior, direct observation and our inference.
Deduplicate reposts and linked quotations; do not count search hits as respondents.

Objects: library, folder, document, page, passage, selection, annotation, form
field, tool preset, open tab, storage connection, revision, export and recipient.
Contexts: studying, research review, professional markup, form completion,
multidocument comparison, intermittent connectivity, cross-device continuation.
These contexts are sampling categories, not claims about market prevalence.

## Verified documented interaction examples

| User job / hypothesis | Documented reference behavior | JETT acceptance direction |
|---|---|---|
| Keep useful tools near the hand | iPad toolbar groups workflows; toolsets toggle, reorder and hide; toolbar can move top/left/right; portrait shows at most three toolsets [1] | Exercise tool switching, side placement, portrait transition and persistent presets without moving the document unexpectedly |
| Work across several files without losing context | Active tab offers rename/reveal/close others; holding allows reordering [2] | Open two files, independently retain position/selection, reorder and close one without losing edits |
| Return to previous thinking | Annotation list sorts by page, jumps to source, searches notes/marked text and filters color [3] | Query a saved note, filter a highlight color, jump to the exact mark and undo with durable readback |
| Act on an area rather than a whole document | iOS selection distinguishes annotation selection and screenshot; offers copy/erase/create-PDF/share [4] | Verify target scope and cancellation; keep screenshot selection distinct from editable PDF data |
| Continue on another device | Official help describes connecting the same cloud storage and syncing edits [5] | Test a real second device, offline changes and conflicts, with visible save/sync state; local backup alone does not satisfy this |

These are documented capabilities, not measured microinteraction timings or
proof that they explain customer affection. User-review evidence is separate.

## First verified user account

The full canonical Reddit thread URL was subsequently accessible:
https://www.reddit.com/r/ipad/comments/17t2dyz/pdf_annotation_app_with_twoway_dropbox_sync_form/

A teacher describes grading over 100 papers, valuing edits to actual PDFs, form
filling and two-way Dropbox sync. Reported friction includes reselecting the pen
for every file, lack of a chosen default zoom, and wanting pressure-driven pencil
opacity rather than thickness alone. Replies describe import/export overhead and
concern about flattening work. This is historical self-report, app version
unspecified, not proof these limitations persist today or a prevalence estimate.

Derived acceptance journey: open a batch of papers, retain a chosen marking tool
and zoom policy, annotate with legible Pencil output, save editable marks to the
intended file, continue on another device and explicitly choose flattening only
when producing a distribution copy. This connects microinteraction friction to
a whole job rather than counting tools.
